# Остатки Яндекс Маркета и алерты

Скил отвечает на вопрос «что скоро закончится и сколько дозаказать». Он берёт остатки по складам, продажи за
период и считает дни запаса по каждому SKU. Всё только чтение: остатки через API скил **не меняет**.

## Когда применять

- «Проверь остатки на Маркете», «какие товары заканчиваются», «утренний отчёт по складу».
- «Настрой алерт: если меньше 10 штук — скажи» (в рамках сессии или по расписанию агента).
- «Сколько заказать, чтобы хватило на 30 дней».

## Что нужно

| Что | Откуда |
|---|---|
| `YM_API_KEY` | Кабинет партнёра Маркета → Настройки → API и модули → API-ключ с доступом «Просмотр товаров и карточек» и «Обработка заказов» |
| MCP `yandex-market` из `tkbk-online/tkbk-mcp` | `ym_campaigns` (магазины и их `campaignId`), `ym_orders` (заказы за период), `ym_offers` (каталог) |
| Node ≥ 20 | `scripts/ym-stocks.mjs` — остатки и оборачиваемость |

```bash
claude mcp add ym -e YM_API_KEY=ключ -- npx -y github:tkbk-online/tkbk-mcp yandex-market
# облако: https://mcp.tkbk.online/mcp/ym с заголовками Authorization: Bearer cr_… и x-ym-api-key
```

Ключ живёт в окружении; в чат его не вставляют, скрипт его не печатает.

## Скрипт

`scripts/ym-stocks.mjs` ходит в `POST https://api.partner.market.yandex.ru/v2/campaigns/{campaignId}/offers/stocks`
(заголовок `Api-Key`), собирает все склады и страницы и печатает по каждому SKU доступный остаток, резерв, брак и
оборачиваемость (для FBY — `turnoverDays`).

```bash
node scripts/ym-stocks.mjs --campaign 12345678                    # таблица остатков
node scripts/ym-stocks.mjs --campaign 12345678 --json             # JSON для расчётов
node scripts/ym-stocks.mjs --campaign 12345678 --min 10           # только SKU, где доступно < 10
node scripts/ym-stocks.mjs --campaign 12345678 --offers SKU1,SKU2 # конкретные SKU
```

`campaignId` — из `ym_campaigns` (это технический id магазина, не номер из кабинета). Для FBS/DBS без групп складов
Маркет отдаёт остатки другим методом (`v3/businesses/{businessId}/offers/stocks`) — скрипт сообщит об этом ошибкой
`400`, тогда передай `--business <businessId>` и он переключится.

## Порядок работы

1. `ym_campaigns` → список магазинов; если их несколько, уточни у пользователя, какие нужны, или обработай все.
2. Для каждого магазина — `scripts/ym-stocks.mjs --campaign <id> --json`.
3. Продажи: `ym_orders` за 14 дней (`days: 14`, статусы кроме `CANCELLED`), посчитай штуки по `offerId`
   (поле `items` в заказах). Скорость продаж = штук / 14.
4. **Дни запаса** = доступный остаток / скорость продаж. Если продаж нет — «нет продаж», не ноль.
   Если у товара есть `turnoverDays` от Маркета — покажи рядом, это официальная оценка.
5. Пороги алерта: по умолчанию **< 7 дней запаса** или **< 10 штук** — красный, 7–14 дней — жёлтый. Пользователь может
   задать свои (`--min`, свои дни).
6. Рекомендация к дозаказу = скорость продаж × горизонт (по умолчанию 30 дней) − доступный остаток − в пути (если
   пользователь сказал, что в пути). Округли вверх до упаковки, если известен размер упаковки.
7. Отчёт (ниже). Если пользователь просил «алерт» — коротко: только красные позиции, одной строкой каждая.

## Формат отчёта

```
Остатки Яндекс Маркет — магазин <название> (<campaignId>), <дата>
🔴 Срочно (< 7 дней): SKU · название · остаток · продаж/день · дней · дозаказать N
🟡 Скоро (7–14 дней): …
Без продаж 14 дней, остаток > 0: K позиций (список по запросу)
Брак / карантин / просрочка: … (если есть)
```

## Правила

- Только чтение. Передача остатков в Маркет (`PUT …/offers/stocks`) — отдельная задача и только по явной просьбе
  с подтверждением списка SKU и количеств.
- Не смешивай магазины: у каждого свой `campaignId` и свои склады.
- Остатки «FIT» включают резерв; для расчёта бери `AVAILABLE`, если он есть, иначе `FIT − FREEZE`.
- Если скорость продаж посчитана меньше чем по 5 заказам — пометь «мало данных».

## Ошибки

| Ответ | Что значит | Что делать |
|---|---|---|
| `401` | нет ключа или неверный | проверить `YM_API_KEY` |
| `403` | у ключа нет нужного доступа | перевыпустить ключ с доступом к товарам и заказам |
| `400` с текстом про склады/группы | модель FBS без групп складов | `--business <businessId>` |
| `420` / `429` | лимит Маркета | подождать `Retry-After` и повторить |
