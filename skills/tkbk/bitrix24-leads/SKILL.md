# Лиды в Битрикс24

Скил помогает отделу продаж не терять входящие: показывает новые лиды, находит дубли, заводит лид из письма или чата
и ставит задачу ответственному. Любое создание или изменение в CRM — только после подтверждения пользователя.

## Когда применять

- «Какие лиды пришли сегодня / без ответа», «сводка по лидам за неделю».
- «Создай лид из этого письма / переписки / заявки с сайта».
- «Поставь задачу Иванову перезвонить завтра в 11:00».
- «Есть ли этот телефон в CRM» — перед созданием лида.

## Что нужно

| Что | Откуда |
|---|---|
| MCP `bitrix24` из `tkbk-online/tkbk-mcp` | `b24_leads`, `b24_deals`, `b24_add_lead`, `b24_add_task` |
| `BITRIX24_WEBHOOK_URL` | Битрикс24 → Приложения → Разработчикам → Другое → **Входящий вебхук**, права `crm`, `task`, `user`. Вид: `https://<портал>.bitrix24.ru/rest/<id>/<код>/` |

```bash
claude mcp add b24 -e BITRIX24_WEBHOOK_URL=https://portal.bitrix24.ru/rest/1/code/ -- npx -y github:tkbk-online/tkbk-mcp bitrix24
# облако: https://mcp.tkbk.online/mcp/b24, заголовок x-b24-webhook
```

Вебхук — это секрет (в нём код доступа). В чат его не вставляют, в отчёты не печатают.

Для операций, которых нет в MCP (статусы, дубли, список сотрудников), используй REST напрямую: `GET <вебхук>/<метод>.json?параметры`.
Хост — только портал пользователя из `BITRIX24_WEBHOOK_URL`.

| Метод | Для чего | Пример параметров |
|---|---|---|
| `crm.lead.list` | лиды с фильтром | `filter[STATUS_ID]=NEW&order[DATE_CREATE]=DESC&select[]=ID&select[]=TITLE&select[]=PHONE&select[]=ASSIGNED_BY_ID&select[]=DATE_CREATE` |
| `crm.status.list` | справочник статусов лидов | `filter[ENTITY_ID]=STATUS` |
| `crm.duplicate.findbycomm` | дубли по телефону/почте | `type=PHONE&values[]=+79990000000` → id лидов, контактов, компаний |
| `user.get` | сотрудники (id для задач) | `filter[ACTIVE]=true` |
| `crm.lead.update` | сменить статус / ответственного | `id=123&fields[STATUS_ID]=IN_PROCESS` — только по подтверждению |
| `crm.timeline.comment.add` | комментарий в карточку | `fields[ENTITY_TYPE]=lead&fields[ENTITY_ID]=123&fields[COMMENT]=…` |

Списки отдаются по 50: следующая страница — параметр `start` из поля `next` ответа.

## Сценарий 1 — сводка по лидам

1. `b24_leads` (новые первыми); при необходимости `crm.lead.list` с фильтром по статусу `NEW` и дате.
2. Раздели: без ответственного · новые старше 1 часа в рабочее время · новые старше 24 часов · остальные.
3. Отчёт:

```
Лиды Битрикс24 на <дата время>
Новых: N (без ответственного: K) · старше 24 ч без движения: M
⚠ Срочно: #id · название · источник · телефон (маска +7 *** *** 12 34) · создан · ответственный
Сделок в работе: X на сумму Y ₽ (по b24_deals)
```

Телефоны и почту в сводке маскируй, полные показывай только по запросу.

## Сценарий 2 — лид из письма или переписки

1. Вытащи из текста: имя, компания, телефон, почта, что нужно, срок, бюджет, источник (письмо / сайт / Telegram /
   звонок). Чего нет — не выдумывай, оставь пустым.
2. Нормализуй телефон к `+7XXXXXXXXXX`.
3. Проверь дубли: `crm.duplicate.findbycomm` по телефону и по почте. Если нашлось — покажи пользователю и предложи
   не создавать новый лид, а добавить комментарий в существующий (`crm.timeline.comment.add`) или поставить задачу.
4. Покажи карточку будущего лида таблицей и спроси подтверждение.
5. `b24_add_lead`: `title` (формат «<Что нужно> — <Компания или имя>»), `name`, `phone`, `email`, `comment`
   (исходный текст запроса целиком, 1–2 абзаца), `confirm: true` — только после «да» пользователя.
6. Если пользователь назвал ответственного — сразу `b24_add_task` (ниже).

## Сценарий 3 — задача менеджеру

1. Найди `responsibleId`: `user.get` по фамилии или имени; если совпадений несколько — уточни.
2. Срок: переведи «завтра в 11» в ISO с часовым поясом пользователя (спроси, если не знаешь; по умолчанию Москва
   `+03:00`).
3. `b24_add_task`: `title` («Перезвонить <клиент> по лиду #<id>»), `responsibleId`, `description` (контекст: что
   обещали, ссылка на лид `https://<портал>.bitrix24.ru/crm/lead/details/<id>/`), `deadline`, `confirm: true` после подтверждения пользователем.

## Правила

- Создание и изменение — только с подтверждением; чтение — свободно.
- Один запрос = одно действие в CRM. Не заводи массово лиды из списка без явного «создай все N».
- Не меняй ответственного и не закрывай лиды «на всякий случай».
- Персональные данные клиентов не выноси за пределы CRM и ответа пользователю (152-ФЗ).
- Коробочный Битрикс24 (свой домен) на облачном MCP TKBK не поддерживается — только локальный запуск.

## Ошибки

| Ответ | Что значит | Что делать |
|---|---|---|
| `401` / `INVALID_CREDENTIALS` | вебхук отозван или код неверный | перевыпустить вебхук |
| `insufficient_scope` | у вебхука нет права `crm` / `task` / `user` | добавить права в настройках вебхука |
| `QUERY_LIMIT_EXCEEDED` | лимит 2 запроса/сек | подождать секунду и повторить |
| пустой `user.get` | нет права `user` | добавить право или попросить id сотрудника |
