# Follow-up по сделкам amoCRM

Сделка, по которой никто не писал неделю, почти всегда теряется. Скил находит такие сделки, пишет для каждой
короткое персональное сообщение под её этап и фиксирует это в CRM: примечание в сделке и задача менеджеру.
Сообщения клиентам скил **сам не отправляет** — только готовит.

## Когда применять

- «Какие сделки зависли», «кого дожать на этой неделе», «сделки без активности 5 дней».
- «Напиши follow-up по сделкам на этапе „КП отправлено“».
- «Поставь задачи менеджерам по всем сделкам без движения».

## Что нужно

| Что | Откуда |
|---|---|
| MCP `amocrm` из `tkbk-online/tkbk-mcp` | `amo_leads` (сделки: id, название, бюджет, статус, воронка, дата), `amo_contacts` (поиск по имени, телефону, почте), `amo_add_note` (примечание в сделку) |
| `AMOCRM_DOMAIN` | адрес аккаунта: `company.amocrm.ru` (или `.amocrm.com`, `kommo.com`) |
| `AMOCRM_TOKEN` | amoCRM → Настройки → Интеграции → своя интеграция → **долгосрочный токен** |

```bash
claude mcp add amo -e AMOCRM_DOMAIN=company.amocrm.ru -e AMOCRM_TOKEN=токен -- npx -y github:tkbk-online/tkbk-mcp amocrm
# облако: https://mcp.tkbk.online/mcp/amo, заголовки x-amo-subdomain и x-amo-token
```

Токен — секрет: в чат не вставлять, в вывод не печатать.

Для того, чего нет в MCP, вызывай API v4 напрямую: `https://<AMOCRM_DOMAIN>/api/v4/...` с заголовком
`Authorization: Bearer <AMOCRM_TOKEN>`. Хост — только домен аккаунта пользователя.

| Запрос | Для чего |
|---|---|
| `GET /api/v4/leads/pipelines` | воронки и этапы (id статусов, их названия и порядок) |
| `GET /api/v4/leads?with=contacts&order[updated_at]=asc&limit=250&page=N` | сделки, самые давно не тронутые первыми; `updated_at` — unix-время |
| `GET /api/v4/leads/{id}?with=contacts` | одна сделка с контактами |
| `GET /api/v4/events?filter[entity]=lead&filter[entity_id][]={id}&limit=10` | последние события по сделке (кто и когда что менял) |
| `GET /api/v4/users` | менеджеры (id, имя) |
| `POST /api/v4/tasks` | задача: `[{"text": "…", "complete_till": <unix>, "entity_id": <leadId>, "entity_type": "leads", "task_type_id": 1, "responsible_user_id": <id>}]` (`1` — звонок, `2` — встреча) |

Системные статусы: `142` — успешно реализовано, `143` — закрыто и не реализовано; такие сделки пропускай.

## Порядок работы

1. **Воронка.** `GET /api/v4/leads/pipelines` → запомни названия этапов. Если воронок несколько — уточни у
   пользователя или возьми основную (`is_main`).
2. **Зависшие.** `amo_leads` (и при необходимости `GET /api/v4/leads` с сортировкой по `updated_at`); отбери
   открытые сделки, у которых `updated_at` старше **N дней** (по умолчанию 5; пользователь может задать). Исключи
   статусы 142/143 и сделки с задачами на сегодня-завтра, если пользователь просил не дублировать.
3. **Контекст.** Для каждой: контакт (`with=contacts`, при необходимости `amo_contacts`), бюджет, этап, последнее
   примечание / событие. Чем закончился последний контакт — главное для текста.
4. **Черновики.** Одно сообщение на сделку, 2–4 предложения, по правилам ниже. Таблица:
   `№ | сделка | этап | дней без движения | менеджер | сообщение | задача (когда)`.
5. **Подтверждение.** Пользователь утверждает всё, часть или правит.
6. **Фиксация.** Для утверждённых: `amo_add_note` с текстом «Follow-up (черновик агента): …» и `confirm: true` — только после подтверждения;
   `POST /api/v4/tasks` на менеджера сделки (срок — завтра 10:00 по часовому поясу пользователя, если не сказано иное).
7. **Отчёт**: сколько сделок, сколько примечаний и задач, кого не удалось обработать.

## Как писать follow-up

- Обращение по имени, на «вы» (если в CRM видно, что общались на «ты» — на «ты»).
- Первая фраза — про прошлый контакт («в прошлый раз договорились…», «отправили КП 7 октября»), не «напоминаю о себе».
- По этапу:
  - **Новый / квалификация** — уточняющий вопрос по задаче клиента, одно предложение о том, чем можете помочь.
  - **КП / счёт отправлен** — спросить, что в предложении вызывает вопросы; предложить короткий созвон с двумя
    вариантами времени.
  - **Переговоры / согласование** — зафиксировать, что осталось решить, и предложить следующий шаг.
  - **Ждём оплату** — вежливо уточнить срок, предложить помочь с документами.
- Без давления и дедлайн-манипуляций («только сегодня»), без скидок, которых пользователь не называл.
- Канал (почта, мессенджер, звонок) — как в последнем контакте. Для звонка вместо сообщения — тезисы разговора.
- Не отправляй ничего клиентам сам: нет инструмента, и это решение менеджера.

## Правила

- Только примечания и задачи; этапы и бюджеты сделок не менять.
- Не трогай сделки, за которыми закреплён другой менеджер, если пользователь просил только свои.
- Персональные данные клиентов — только внутри CRM и ответа пользователю.
- Лимит amoCRM — 7 запросов в секунду; между страницами делай паузу.

## Ошибки

| Ответ | Что значит | Что делать |
|---|---|---|
| `401` | токен истёк или отозван | перевыпустить долгосрочный токен в интеграции |
| `403` | нет прав у пользователя интеграции | проверить права в amoCRM |
| `429` | превышен лимит | подождать и повторить |
| `402` | аккаунт не оплачен | сообщить пользователю |
