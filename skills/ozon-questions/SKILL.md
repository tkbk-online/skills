# Вопросы покупателей на Ozon

Покупатели Ozon задают вопросы в карточке товара; продавец, который отвечает быстро и по делу, получает больше
заказов. Скил забирает новые вопросы, пишет ответы с опорой на реальные данные о товаре и публикует их только после
подтверждения пользователя.

## Когда применять

- «Ответь на новые вопросы на Ozon», «что спрашивают про артикул X», «сколько вопросов без ответа».
- Ежедневная рутина: закрыть все вопросы со статусом `NEW`.

## Что нужно

| Что | Откуда |
|---|---|
| `OZON_CLIENT_ID`, `OZON_API_KEY` | Кабинет продавца Ozon → Настройки → Seller API → сгенерировать ключ (роль с доступом к вопросам и ответам) |
| Node ≥ 20 | для `scripts/ozon-questions.mjs` |
| MCP `ozon` из `tkbk-online/tkbk-mcp` (опционально) | `ozon_products`, `ozon_stocks` — проверить наличие и характеристики, чтобы не обещать то, чего нет |

Ключи живут в переменных окружения. Никогда не проси вставить их в чат и не печатай их в выводе: скрипт их не выводит.

```bash
# MCP для остатков и товаров (локально, бесплатно)
claude mcp add ozon -e OZON_CLIENT_ID=123 -e OZON_API_KEY=ключ -- npx -y github:tkbk-online/tkbk-mcp ozon
```

## Скрипт

`scripts/ozon-questions.mjs` — обёртка над методами Seller API (`https://api-seller.ozon.ru`):

```bash
node scripts/ozon-questions.mjs count                       # сколько вопросов по статусам
node scripts/ozon-questions.mjs list --status NEW           # новые вопросы: id, sku, текст, автор, дата
node scripts/ozon-questions.mjs list --status NEW --json    # то же в JSON
node scripts/ozon-questions.mjs answer <question_id> <sku> "Текст ответа"
```

Статусы фильтра: `NEW` (новые), `VIEWED`, `PROCESSED` (отвечены), `UNPROCESSED`, `ALL`. Список отдаётся страницами:
скрипт сам идёт по `last_id`, пока страницы не кончатся. Методы: `POST /v1/question/count`, `POST /v1/question/list`,
`POST /v1/question/answer/create` (тело `{question_id, sku, text}`). Если Ozon вернёт `404` на метод — проверь
актуальную версию в документации Seller API (dev.ozon.ru, раздел «Вопросы и ответы») и поправь константы в начале
скрипта.

## Порядок работы

1. `count` → скажи пользователю, сколько новых вопросов.
2. `list --status NEW --json` → для каждого вопроса определи тип: наличие / размер / совместимость / состав /
   доставка / гарантия / цена / не о товаре.
3. Для вопросов о наличии и характеристиках **сверься с данными**: `ozon_stocks` (по `offer_id`), `ozon_products`,
   карточка товара (описание, характеристики). Не выдумывай характеристики: если данных нет — так и напиши в черновике
   пометку `[уточнить у пользователя]`.
4. Выведи таблицу `№ | sku | вопрос | черновик ответа | источник факта` и спроси подтверждение.
5. Публикуй утверждённые по одному через `answer`. Повтори при `429` через 1–2 секунды.
6. Отчёт: опубликовано / пропущено / требуют уточнения.

## Как писать ответы

- На «вы», 1–4 предложения, сначала прямой ответ на вопрос, потом одна полезная деталь.
- Факты только из карточки, остатков или от пользователя. Не обещай сроки доставки — это зона Ozon.
- Нельзя: контакты, ссылки на другие площадки и сайты, промокоды и «напишите нам в директ», сравнение с конкурентами,
  медицинские обещания.
- Вопрос про цену или скидку → вежливо: цена указана в карточке, акции видны там же.
- Вопрос не о товаре (спам, оскорбления, «где мой заказ») → пропустить, пометить для пользователя.
- Если на один SKU несколько одинаковых вопросов — ответить на каждый, но разными словами, и предложить пользователю
  добавить этот факт в описание товара.

## Ошибки

| Ответ | Что значит | Что делать |
|---|---|---|
| `401` / `403` | неверные Client-Id / Api-Key или у ключа нет прав на вопросы | перевыпустить ключ в кабинете с нужной ролью |
| `404` | метод переехал | сверить путь с документацией Seller API, поправить константы в скрипте |
| `429` | лимит запросов | подождать и повторить тот же вызов |
| `question not found` при ответе | вопрос уже закрыт или удалён | пропустить |
